Command line and CI

The command line runs the same engine as the app, with no network calls. Its output and exit codes are stable, so scripts and CI jobs can rely on them. Start with the install guide if you haven't installed it yet.

Formats

Reports and checks print as markdown. --format picks another format, and --out writes it to a file:

$ openppc audit search-term-waste exports/search_terms.csv --format html --out waste.html
$ openppc audit keyword-audit exports/keywords.csv --format json --out keywords.json
$ openppc check --audit their-audit.md --data exports/search_terms.csv --format sarif --out check.sarif
  • md, the default: the report as you see it in the app.
  • html: one page that opens in any browser, even offline. It loads nothing from anywhere.
  • json, for scripts: the report, whether it passed its own number check, and every fact behind it. Each file says its format_version, which changes only when a reader would break. The schemas are in openppc/schemas.
  • sarif, for check only: each problem at its line in the audit, for GitHub code scanning and other CI tools.

The app downloads any audit as .html or .json too, from the line under the report's header.

Exit codes

CodeMeaning
0The audit ran, or the check found nothing wrong.
1Bad input: a missing or unreadable file, the wrong export, or a mistyped command.
2The check found a wrong number, a wrong label or a contradiction.
3A bug in OpenPPC. Please report it.

A number that can't be checked, like a target or a forecast, is never held against an audit, so it doesn't change the exit code.

Fail the build when an audit invents a number

If your team keeps audits in a repository, the OpenPPC GitHub Action checks each one against the exports it was written from. The job fails when a number doesn't hold up, and the full check appears in the job's summary.

- uses: secondsteplabs/openppc@<commit>  # pin a release's full commit SHA
  with:
    audit: audits/july.md
    data: |
      exports/search_terms_july.csv
      exports/keywords_july.csv
    industry: home-services  # optional

The action installs OpenPPC from the same commit, so pinning the action pins the checker too. Keep client exports in a private repository.

Show problems on the audit's lines

Add sarif and upload the file, and each wrong number appears as a code scanning alert at its line in the audit. The job needs security-events: write.

- uses: secondsteplabs/openppc@<commit>
  with:
    audit: audits/july.md
    data: exports/search_terms_july.csv
    sarif: openppc.sarif
- if: always() && hashFiles('openppc.sarif') != ''
  uses: github/codeql-action/upload-sarif@<commit>
  with:
    sarif_file: openppc.sarif

Docker

The Dockerfile builds two images. The command line image has no MCP library, and both run as an ordinary user. Build them in a clone of the repository:

$ docker build -t openppc .
$ docker run --rm --network none -v "$PWD/exports:/data:ro" openppc audit search-term-waste search_terms.csv
$ docker build --target mcp -t openppc-mcp .
$ docker run --rm -p 8000:8000 openppc-mcp --http --host 0.0.0.0 --port 8000

The command line needs no network, so --network none costs nothing. Mount your exports read-only at /data.

From Python

Five names are the stable API: FactBook, trace, load_report, run_template and the Template protocol. They carry type hints, and a change that breaks one is listed under Breaking in the changelog.

from openppc.engine.trace import trace
from openppc.templates import run_template

markdown, facts, passed = run_template("search-term-waste", "exports/search_terms.csv")
claims, contradictions = trace(markdown, facts)  # each number, and the fact it traced to

The full list of what stays stable between releases is in docs/compatibility.md.
